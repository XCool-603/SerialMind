# SerialMind V0.5 管理模块（CRUD）与 AI 边界

> **这篇补两件事**：
> ① V0.4 只写了"对象是什么"，没写"**怎么管**"——产品、链路、协议、用例的增删改查是日常主力操作，必须是一等公民。
> ② AI 的定位摆错了。**AI 只是辅助生成，不是控制中心。** 配置我说了算，AI 产出草稿，我点"应用"才生效。

***

## 1. 词汇对齐（按你的叫法）

V0.4 里的"项目 / 通道"，按你的习惯改称 **产品 / 链路**：

| 你的叫法   | 含义                         | 之前叫什么          |
| ------ | -------------------------- | -------------- |
| **产品** | 一套被测系统的配置集合（起重机 / 小汽车）     | 项目 Project     |
| **链路** | 一个串口（COM3）+ 参数 + 绑定协议 + 备注 | 通道 Channel     |
| **协议** | 字节 ↔ 字段的翻译规则               | Protocol / PDL |
| **用例** | 步骤 + 断言，跑一遍给结论             | 场景 / 测试        |
| **套件** | 一组用例                       | Suite          |

```
产品 Product（起重机 / 小汽车）
├── 链路 Link        COM3 · 921600 8N1 · 备注"起升PLC"
│     └── 协议 Protocol   帧格式、字段、校验、分帧
├── 规则 Rule        心跳 / 周期 / 条件触发 / 自动应答
├── 用例 Case        步骤 + 断言（可数据驱动）
└── 套件 Suite       用例集合 → 一键跑 → 报告
```

**一个产品下可以有多条链路**（多个串口同时开），每条链路绑一个协议，用例可以指定跑在哪条链路上。

## 2. 通用 CRUD 规范（所有实体统一，8 条）

| # | 能力 | 说明                                      |
| - | -- | --------------------------------------- |
| 1 |    | 左侧树形导航，右侧列表；支持按名称/标签搜                   |
| 2 |    | 空白 / 从模板 / 从现有复制 / 导入 /                 |
| 3 |    | 行内改名（F2）、双击进详情、表单化编辑                    |
| 4 |  ★ | 最高频操作：新机型 = 复制旧产品改几个字段；新协议 = 复制老协议改几个字段 |
| 5 |    | 软删除 + 回收站（30 天），                        |
| 6 |    | 单实体导出 JSON/YAML；整个产品打包导出（可 Git、可分享同事）   |

## 3. 各实体 CRUD 明细

### 3.1 产品 Product

| 操作 | 说明                                                       |
| -- | -------------------------------------------------------- |
| 新建 | 空白 / 从模板（通用 PLC、AGV、自定义）/ 复制现有 / 导入 .smprod / AI 从文档生成草稿 |
| 字段 | 名称、描述、标签、默认串口参数、备注                                       |
| 编辑 | 改名、改描述、加标签                                               |
| 复制 | "复制为新机型"——最常用                                            |
| 切换 | 顶栏下拉切换当前产品，配置全部跟着切（互不干扰）                                 |
| 删除 | 进回收站，30 天可恢复                                             |
| 导出 | 打包整个产品（链路+协议+规则+用例+套件）                                   |

### 3.2 链路 Link（= 一个串口）

| 操作    | 说明                                         |
| ----- | ------------------------------------------ |
| 新建    | 选端口 → 配参数（波特率/数据位/停止位/校验/流控/控制线）→ 绑协议 → 备注 |
| 编辑    | 改参数（连接中允许改，保存后自动重连并提示）；改绑协议                |
| 复制    | 复制成第二条链路（多口对拖场景）                           |
| 启用/禁用 | 禁用后不自动连接、不参与用例                             |
| 删除    | 断连 + 进回收站                                  |
| 状态    | 未连接 / 已连接 / 错误（错误要给人话原因和修复命令）              |
| 特殊    | 端口占用诊断、虚拟串口对（无硬件自测）                        |

### 3.3 协议 Protocol

| 操作     | 说明                                                                 |
| ------ | ------------------------------------------------------------------ |
| 新建     | ① 表单手写 ② YAML 源码手写 ③  ④ 从内置模板（Modbus / AT / NMEA / 自定义二进制）         |
| 编辑     | 字段表（增/删/改/拖拽排序/自动算 offset）、校验配置、分帧配置、字节序（用户可选 ABCD/BADC/CDAB/DCBA） |
| 保存校验 ★ | 保存前必须通过""（组包结果与样例逐字节一致），否则不允许保存或标黄警告                               |
| 复制     | "另存为 v2"——改协议最常见操作                                                 |
| 版本     | 每次保存生成版本，可 diff、可回滚                                                |
| 删除     | 引用检查 → 进回收站                                                        |
| 导入导出   | JSON / YAML 单文件                                                    |

### 3.4 报文 Message（协议内）

帧类型的增删改；字段布局可视化编辑（拖拽调整顺序、自动重算偏移）；每个报文可配默认参数值。

### 3.5 规则 Rule（自动发送）

| 操作    | 说明                                            |
| ----- | --------------------------------------------- |
| 新建    | 选触发器（周期/条件/收到帧/超时/连接建立）→ 配动作（发报文/执行用例/启停其他规则） |
| 编辑    | 表单化；命中次数、上次触发时间实时显示                           |
| 开关    | 单条开关 + 全局"自动发送"总开关                            |
| 复制/删除 | 标准 CRUD                                       |

### 3.6 用例 Case

| 操作 | 说明                                            |
| -- | --------------------------------------------- |
| 新建 | ① 空白手写 ②  ③ （抓一段真实交互 → 自动推断步骤和断言，★很实用） ④ 复制现有 |
| 编辑 | 步骤列表（增删改/拖拽排序）、断言编辑、绑定数据源（CSV）                |
| 运行 | 单条运行 / 单步调试 / 加入套件                            |
| 复制 | 改一个点位就是新用例                                    |
| 版本 | 保存历史 + diff                                   |
| 删除 | 进回收站                                          |

### 3.7 套件 Suite

用例集合；支持排序、分组（冒烟/全量/专项）、一键跑、循环 N 次、导出报告。

## 4. 管理界面结构

```
┌─ 顶栏：当前产品 [起重机 ▾] ─────────────── 自动发送 [开] ─ 运行套件 ─┐
├────────────┬──────────────────────────────────────┬──────────────┤
│ 产品树      │ 列表区（当前分类的实体）                │ 详情/编辑区   │
│            │                                      │              │
│ ▾ 起重机    │ 名称          状态    引用   更新时间  │ ┌──────────┐ │
│   ▾ 链路    │ COM3 起升PLC  已连接  协议v2  10:22   │ │表单/字段表│ │
│     COM3    │ COM5 小车PLC  未连接  协议v2  09:10   │ │          │ │
│   ▾ 协议    │                                      │ │[保存][复制]│ │
│     起升v2  │ ＋新建  ⧉复制  ⬇导出  🗑删除          │ └──────────┘ │
│   ▾ 规则    │                                      │              │
│   ▾ 用例    │                                      │              │
│   ▾ 套件    │                                      │              │
├────────────┴──────────────────────────────────────┴──────────────┤
│ 运行日志 / 终端（收发区，随时切回来）                                │
└──────────────────────────────────────────────────────────────────┘
```

**关键**：管理区和收发终端是**同一窗口的两个视图**，可随时切换或分屏——不是"设置页"。因为配置资产（协议、用例）是核心价值，管理是日常主力操作。

## 5. ★ AI 的边界（这篇的重点）

### 5.1 一句话定位

> **AI 是个打字快的助手，不是老板。** 它产出**草稿**，我点"应用"才生效。

### 5.2 能做什么 / 不能做什么

| ✅ AI 能做            | ❌ AI 不能做       |
| ------------------ | -------------- |
| 生成草稿：协议、链路配置、用例、数据 | 直接写入生效（必须我确认）  |
| 填充表单、给出建议          | 自动修改我已有的配置     |
| 解释、分析、找原因          | 自动执行发送 / 自动跑测试 |
| 从文档、录制、一句话里推断      | 替我决定任何事        |

### 5.3 交互范式：草稿区

所有 AI 产出都进**草稿区**，不直接进正式配置：

```
┌─ AI 草稿 ──────────────────────────────────────┐
│ 来源：sensor_manual_v2.pdf（第 3.2 节）         │
│ 生成：协议「起升-新」12 个字段 + CRC16/MODBUS   │
│                                                │
│  ⚠ 2 项待确认：                                 │
│    · 字段"数据域"长度：文档未写明 → 用样例帧推断 │
│    · 字节序：样例帧匹配 CDAB（字交换）           │
│                                                │
│  [预览 diff]  [全部应用]  [逐条应用]  [丢弃]    │
└────────────────────────────────────────────────┘
```

* **必须显示 diff**：应用前能看到"将新增什么、修改什么"。
* **可以逐条应用**：12 个字段我只要 10 个，其余丢掉。
* **可以修改后再应用**：草稿是可编辑的。
* **应用后可撤销**：`Ctrl+Z` 或版本回滚。

### 5.4 权限分级（用户可配，默认 L1）

| 级别             | 行为                 | 适用         |
| -------------- | ------------------ | ---------- |
| **L0 关闭**      | 完全不调用 AI，所有功能照常    | 涉密环境 / 不信任 |
| **L1 只建议**（默认） | AI 输出到草稿区，我手动应用    | 绝大多数情况     |
| **L2 自动填充**    | AI 直接填进表单，但我点保存才生效 | 熟练后想省事     |
| **L3 自动应用**    | ——                 |            |

### 5.5 三条硬约束

* **AI 可完全关闭**。关掉之后所有功能必须照常可用——手动 CRUD 是完整的第一等能力，AI 只是"少打字"的加速器。**没有 AI 它也得是个完整好用的工具。**
* **AI 不许静默改配置**。任何 AI 变更必须：① 有 diff ② 我点了确认 ③ 记审计日志（谁改的、AI 用的哪份文档、什么时候）。
* **AI 的猜测必须标出来**。文档没写清的字段、不确定的校验算法、推断的字节序，一律在草稿里高亮"待确认"，绝不静默填一个看起来合理的值。

### 5.6 审计

每次 AI 应用记录：`时间 / 操作人 / 来源文档或指令 / 改了什么（diff）/ 可回滚`。出问题时能查"这个字段是谁、凭什么这么配的"。

## 6. AI 辅助自动化测试（4 种用法）

| 用法              | 输入                                            | 输出                             |
| --------------- | --------------------------------------------- | ------------------------------ |
| **① 一句话生成用例**   | "测一下 1 号点位走到 3 号点位，位置 3 秒内必须到 3000，到位标志必须置 1" | 用例草稿（步骤 + 断言），进草稿区             |
| **② 从录制生成用例** ★ | 抓一段真实成功的交互（我手动跑通一次）                           | 自动推断出步骤序列 + 断言骨架，我再删改          |
| **③ 补断言**       | 已有用例                                          | 建议"还应该断言什么"（漏了 CRC 检查、漏了无多余帧等） |
| **④ 失败分析**      | 失败步骤的期望 vs 实际 + 原始字节                          | 可能原因排序 + 建议下一步查什么              |

**② 是我认为最实用的**：不用从零写用例——**我先手动把流程跑通一遍，让它把这次交互录下来，自动转成用例骨架**，我只补断言。这比"让 AI 凭空写用例"可靠得多。

## 7. 数据模型补充

| 表/字段                                                | 说明                    |
| --------------------------------------------------- | --------------------- |
| `product`                                           | 产品（原 project）         |
| `link`                                              | 链路（原 channel），含备注文本字段 |
| `protocol` / `protocol_version`                     | 协议与版本历史               |

| `rule` / `rule_stat`                                | 自动发送规则与统计             |

| `audit_log` ★                                       | 审计（含 AI 应用记录）         |
| `deleted_at`                                        | 所有实体加软删除字段（回收站）       |

## 9. 开放问题

* **"产品"是顶层吗？** 我按"产品 = 起重机/小汽车 = 最顶层"理解。如果你的实际结构是"客户 → 产品 → 机型"这种多层，告诉我，我加一层。
* **一个产品下会有几条链路同时开？** 2\~3 条（多口对拖）还是更多？影响多链路 UI 布局。
* **用例你自己写的比例有多少？** 如果大部分你都想自己写，AI 用例生成的优先级可以降；如果大部分想 AI 生成，那"从录制生成"要提前做。
* **协议变更后，旧用例要不要自动适配？** 比如字段改名了，用例里引用的字段失效——是自动映射、还是报错让我手动改？
