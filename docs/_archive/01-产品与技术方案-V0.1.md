# SerialMind —— 跨平台智能串口调试工作台

> **一句话定位**：一个长得像 2025 年的 SScom —— 跨平台、协议可编程、把"协议文档"一键变成"能点的调试面板"。
> **版本**：V0.1 草案 ｜ **代号**：SerialMind（备选 PortSmith / FrameLens）｜ **对标**：SScom 5.x、XCOM、SecureCRT、Serial Studio
> **本文结构**：A 产品篇（产品需求文档） + B 技术篇（技术设计文档）

***

# A. 产品篇

## A1. 摘要与三条红线

### 三根支柱

| 支柱      | 含义                                             | 为什么难被抄                     |
| ------- | ---------------------------------------------- | -------------------------- |
| **好看**  | 暗色优先、字段级着色、虚拟滚动、克制动效、可导入主题                     | 需要完整设计系统，不是换皮肤             |
| **跨平台** | Win / macOS / Linux 体验一致，包体 < 25 MB，冷启 < 1.5 s | Tauri + Rust，非 Electron 套壳 |
| **智能**  | 协议文档（PDF/Word/C 头/样例报文）→ 结构化协议定义 → 自动生成调试面板    | 需要"LLM + 确定性校验器 + 样例帧自测"闭环 |

### 用户价值

> 以前：拿到 30 页协议文档 → 手算 CRC、手敲 16 进制、对着字节数偏移 → 半天才发出第一帧。
> 现在：文档拖进来 → 30 秒得到带字段名、枚举下拉、CRC 自动算的调试表单 → 点发送。

### 三条产品红线（防止做成四不像）

* **不做 IDE**。脚本能力只服务于造帧 / 判包 / 批测。
* **AI 不许静默猜**。无法从文档确定的字段（尤其校验算法）必须标"待确认"并给候选。
* **离线可用是底线**。不配 AI Key 时必须是一个完整好用的传统串口工具。

## A2. 背景：SScom 到底哪里不够用

SScom 优点是极轻、极快、零学习成本，但能力模型停在 2008 年：

| 维度   | SScom 现状          | 实际痛点                  |
| ---- | ----------------- | --------------------- |
| 平台   | 仅 Windows（Win32）  | macOS/Linux/ARM 完全不可用 |
| 界面   | 固定字号配色，DPI 不友好    | 4K 屏字小如蚁，长时间盯屏疲劳      |
| 协议层  | 只有 HEX / ASCII 视图 | ，字段含义靠脑子记             |
| 造帧   | 手敲十六进制，CRC 要外部工具  | 改一个字段要重算 CRC，易错       |
| 快捷发送 | 有限静态列表            | 无法参数化、无法从协议自动生成       |
| 多端口  | 弱                 | 无法多口对拖、无法并排对比         |
| 高吞吐  | 高波特率刷屏假死          | 921600 持续输出会卡 UI      |
| 数据   | 纯文本日志             | 无结构化、无回放、无图表          |
| 自动化  | 无                 | 产线批测只能人肉点             |

> **结论**：SScom 的"轻"值得继承，"不懂协议"必须解决。竞品里 Serial Studio 解决了可视化、YAT/Termite 解决了跨平台，**但没有一个解决"协议文档 → 可执行调试界面"的转化**。这就是切口。

## A6. 功能地图

* **连接层**：端口枚举/热插拔、参数（含自定义波特率）、DTR/RTS 控制线、端口占用诊断（给出占进程与修复命令）、自动重连、多会话分屏、**内置虚拟串口对**（无硬件自测）
* **终端层**：ASCII / HEX / **混合**三态、时间戳多格式、**字段级着色**、折叠重复帧、搜索过滤、环形缓冲 + 落盘、导出 TXT/CSV/JSON/HTML
* **发送层**：HEX 智能分组、快捷发送树（分组/拖拽/参数化）、定时循环（随机抖动）、文件发送、变量宏
* **协议层 ★**：PDL 定义、校验算法库、5 种分帧策略、双向组包解包、请求响应配对与 RTT、内置模板（Modbus RTU/ASCII、DL/T 645、NMEA、AT、SCPI）
* **AI 层 ★**：文档→定义、样例帧自测、自然语言组包、实时异常分析、协议问答
* **可视化层**：字段实时曲线、帧率/长度分布/错误率统计、位波形、可拖拽仪表盘
* **数据层**：录制（原始字节 + 元数据，可回放）、回放（时间轴/倍速/步进）、工作区（一键恢复）
* **自动化层**：JS 脚本（QuickJS 沙箱）、YAML 测试用例、批量执行报告、**CLI headless 模式**（可进 CI/产线工装）

## A8. 功能规格要点

**连接**：波特率 1\~20,000,000 自定义；校验 None/Odd/Even/Mark/Space；流控 RTS-CTS/XON-XOFF；打开失败必须区分 `PermissionDenied`（Linux 需 dialout 组）/ `Busy`（提示占用进程名）/ `NotFound`，并给出**可复制的修复命令**。

**终端**：行结构 = `时间戳 │ 方向 │ 帧序号 │ 原始字节 │ 解析摘要`；同帧内不同字段用语义色（地址紫/功能码蓝/数据默认/CRC 灰/错误红）；环形缓冲默认 50 MB（8\~512 可配），超限转磁盘并释放内存；超过 X 帧/秒时降采样显示 + "已省略 M 条"提示，但**完整落盘不丢**。

**发送**：HEX 模式自动忽略空格与 `0x`；ASCII 支持 `\r \n \t \xNN` 转义；`↑/↓` 调历史；危险命令（写/擦除/复位/升级）二次确认，可白名单。

**协议**：同一份定义双向可用（解包 + 组包），不存在两套配置；校验失败标记错误帧但**仍尽力解析**（便于排障）；未配对的响应标"孤儿帧"。

**AI 导入 5 步**：① 导入 → ② 抽取 → ③ 校验 → ④ 人工确认 → ⑤ 生成面板，**每步可回退**。

## A9. AI 能力规格（产品视角）

### 四个原则

| 原则                   | 落地                                      |
| -------------------- | --------------------------------------- |
| LLM 只做"理解与翻译"，不做"计算" | CRC/长度/偏移一律由确定性代码验证，LLM 只提候选            |
| 结构强约束                | 强制 JSON Schema（function calling），拒绝自由文本 |
| 闭环自证                 | 用用户提供的样例报文 round-trip，不通过不许"完成"         |
| 可回溯可回退               | 每字段带原文出处 + 置信度；生成物是草案，人工确认才落库           |

### 输入与预处理

文本 / PDF / DOCX / 图片截图 / **C 头文件** / 抓包日志 / 样例报文 →
① 归一化（PDF→文本+表格，DOCX→MD，图片→多模态 OCR，C 头→tree-sitter 解析 struct/enum）→
② **确定性预处理**（表格行列对齐、struct 字段提取、样例帧长度与疑似校验位分析）→
③ 协议族识别（Modbus / DL645 / NMEA / AT / SCPI / 自定义二进制 / TLV / 文本行）→
④ **分块两级抽取**（Pass A 帧骨架，Pass B 逐字段细化，避免长上下文遗忘）

> **关键洞察**：C 头文件与结构化表格比自由文本可靠一个数量级，应优先用确定性解析器，LLM 只补人话描述。这是准确率从 70% 拉到 90% 的关键。

### 防幻觉：确定性校验器

| 检查            | 规则                    | 失败处理                      |
| ------------- | --------------------- | ------------------------- |
| 字段连续性         | 无重叠、无空洞（除显式 reserved） | 回喂 LLM 修正（≤3 轮）           |
| 长度自洽          | 字段 size 求和 / 表达式可求值   | 同上                        |
| **校验算法判定**    | 对候选（未指定时）用样例帧计算并与帧尾比对 | 唯一命中→自动确定；多命中→让用户选；零命中→标红 |
| Round-trip    | 组包结果与样例帧              | 高亮差异字节（期望/实际）             |
| 枚举合理性 / 大小端一致 | 值与位宽匹配、字节序与样例帧推断一致    | 警告                        |

> **校验算法穷举是杀手锏**：只要给一帧样例，CRC 是 MODBUS 还是 CCITT 是**算得出来**的，不需要问模型。把可计算问题从 LLM 手里拿走，是可靠性的分水岭。

**自动纠错循环**：Validator 失败 → 把"原文片段 + 上次输出 + 具体错误"回喂 → 降 temperature 重试 ≤3 轮 → 仍失败则**降级为部分完成**（通过字段保留，问题字段标红交给人）。

### 人工确认界面

左：原文（可点选跳转高亮）｜ 右：字段表（#/名称/偏移/长度/类型/置信度），低置信度**黄底**，`unresolved` 顶部横幅；校验算法未确定时给候选单选项并标注"样例帧匹配 ✓/✗"；任何修改后**毫秒级本地重新校验**，显示"✓ 通过样例帧"。

### 自然语言 → 动作

意图分类（组包发送/解析解释/脚本生成/配置修改/问答）→ 注入当前 PDL + 端口配置 + 最近 10 帧摘要 → LLM 输出结构化动作 JSON → **本地校验**（字段范围、危险命令、PDL 合法性）→ 预览卡片（可编辑）→ 用户确认才执行。

### 实时分析（控成本）

**永远不喂原始字节流**，喂"体征摘要"（500\~1500 token）：帧率、CRC 错误率、超时数、长度离群、RTT p50/p99、异常样本。

| 场景       | 模型档位     | 单次成本           |
| -------- | -------- | -------------- |
| 协议文档抽取   | 强模型      | ¥0.05\~0.3 / 份 |
| 自然语言指令   | 中等模型     | < ¥0.01        |
| 实时异常解释   | 小模型 + 缓存 | < ¥0.005       |
| 规则引擎（本地） | 无模型      | 0              |

**两级触发**：本地规则引擎（CRC 错/超时/长度异常/越界/重复帧/频率突变/状态机非法跳转）永远开、零成本；LLM 仅在用户点击、规则报警且开启自动诊断、或用户提问时调用。重复故障走缓存不重复付费。

### 模型网关与隐私

OpenAI 兼容协议为默认（覆盖 DeepSeek、通义、Kimi、智谱、vLLM、Ollama、LM Studio）；Key 存操作系统钥匙串，**绝不明文入库或日志**；默认只上传文档文本与样例帧，不上传完整日志；可开"禁止上传原始报文"（会降低校验算法判定，需提示）；企业可配私有网关或全离线。

**离线兜底**：C 头解析、表格解析、CRC 枚举、模板匹配全部本地可跑，无网也能拿到约 60% 的自动化收益。

### AI 验收指标

| 能力         | 指标            | 目标        |
| ---------- | ------------- | --------- |
| 协议抽取       | 字段名/偏移/类型 F1  | ≥ 0.90    |
| 校验算法       | 有样例帧时判定准确率    | ≥ 0.95    |

| 响应时延       | 抽取首字返回        | < 3 s（流式） |

## A10. 界面与视觉规范

**设计语言**：工程仪表的冷静 × 现代软件的通透 × 恰到好处的呼吸感。

## B3. 高吞吐数据通道（能不能扛住的核心）

```
串口 OS 线程（blocking read）
  → 分帧器（按 PDL framing 切帧，Rust 侧完成）
  → 批量聚合（16 ms 或 64 KB，先到为准）
  → Tauri Channel 二进制推送（非 JSON event）
     载荷 = [u32 头长度][JSON 元数据][原始字节区]
  → 前端写入环形缓冲 → 虚拟列表只渲染可视区
```

五条要点：

* **分帧在 Rust 做**，前端只显示，避免 JS 处理百万级字节。
* **二进制 IPC**：Tauri 2 的 `InvokeBody::Raw` / `Response`，比 JSON 快 5\~10 倍、体积小 3 倍。
* **批量推送**：每 16 ms 一批，避免 IPC 风暴。
* **背压**：前端慢时丢弃"显示用"数据但**完整落盘**，提示"显示已降采样"。
* **降采样**：超阈值只显示每 N 帧一条 + "已省略 M 条"，用户可关。

## B4. AI 流水线（Rust 侧）

```
sn-ai::ingest
  ├ detect_format()     pdf/docx/md/text/c-header/image/capture
  ├ normalize()         → Document { sections, tables, structs, samples }
  ├ classify_family()   规则+关键词 → modbus-rtu / nmea / custom …
  ├ select_chunks()     只挑"帧格式/寄存器表/命令表"章节（省 token 且更准）
  ├ build_prompt()      system + few-shot + JSON Schema + 上下文
  ├ call_provider()     流式、可中断、可重试
  ├ parse_structured()  Schema 强校验 + 截断容错修复
  ├ validate()          第 A9 章校验器
  ├ self_repair()       ≤3 轮
  └ emit_progress()     前端渐进渲染（骨架先出、字段逐个填）
```

**渐进渲染**：流式 JSON 边到边增量解析，用户立刻看到"识别到 12 个字段…"而不是等 20 秒一次性出结果 —— 体验差异化的关键细节。

## B5. PDL 协议描述语言（草案）

设计原则：JSON 为唯一真源（YAML 为书写语法，双向转换）；声明式优先，表达式/脚本作逃生舱；**同一份定义双向可用**；一切可寻址（字段有稳定 id 供 UI/脚本/AI 引用）。

```jsonc
{
  "pdlVersion": "1.0",
  "id": "proto_modbus_rtu",
  "name": "Modbus RTU",
  "family": "modbus-rtu",
  "transport": { "kind": "serial",
    "defaults": { "baudRate": 9600, "dataBits": 8, "parity": "none", "stopBits": 1 } },
  "framing": { "mode": "silence-gap", "gapMs": 3.5 },
  "endian": "big",
  "fields": [
    { "id": "addr", "name": "从站地址", "offset": 0, "size": 1, "type": "uint" },
    { "id": "func", "name": "功能码", "offset": 1, "size": 1, "type": "uint",
      "enum": { "1": "读线圈", "3": "读保持寄存器", "6": "写单寄存器", "16": "写多寄存器" } },
    { "id": "payload", "name": "数据域", "offset": 2, "type": "bytes",
      "sizeExpr": "byteLength - 4" },
    { "id": "crc", "name": "CRC16", "type": "checksum",
      "algorithm": "crc16/modbus", "range": { "from": 0, "to": "byteLength - 2" },
      "endian": "little" }
  ],
  "requests": [ /* 命令模板：read_holding_registers … */ ]
}
```

**分帧策略**：`silence-gap`（静默间隔，Modbus RTU）/ `fixed-length` / `delimiter`（AT、文本行）/ `length-field`（偏移+宽度+是否含头含校验）/ `script`（极端变长），可组合（先找 `AA 55` 头再读长度）。

**字段类型**：uint / int / float / bcd / bool / **bitfield** / enum / bytes / string(ascii·utf8·gbk) / array / tlv / reserved / nested / timestamp，通用参数含 offset、size、scale、unit、format。

**校验算法库**：crc8、crc16/modbus、crc16/ccitt-false、crc16/xmodem、crc16/ibm、crc32/iso-hdlc、sum8/sum16、xor8、lrc、bcc、fletcher16/32、custom（表达式）。

**表达式语言**（逃生舱）：四则/比较/三元 + `len`、`offset`、`prev.<fieldId>`、`bytes[i]`、`hex()`、`crc()`；**必须沙箱求值**（禁 IO、限指令数）；TS 侧实现同语法解释器用于编辑器实时预览，并有一致性测试保证两端结果相同。

**版本**：PDL 带 `pdlVersion`，向后兼容 ≥2 个大版本；协议有版本历史，支持 diff 与回滚，会话可绑定具体版本。

## B6. 数据模型

| 表                                       | 说明                    |
| --------------------------------------- | --------------------- |
| `workspace`                             | 工作区（布局、名称）            |
| `session`                               | 会话（端口配置、绑定的协议与版本）     |

| `ai_thread` / `ai_message` / `ai_cache` | AI 会话、用量与成本、结果缓存      |
| `setting`                               | 设置（，密钥在钥匙串）           |
| `recording`                             | 录制索引                  |

**文件布局**：`<AppData>/serialmind/` 下 db.sqlite、recordings/、logs/、protocols/（可 Git 管理）、themes/、crash/。

**录制格式&#x20;****`.srec`**：magic + 版本 + JSON 元数据 → `[时间戳 varint][方向][长度 varint][字节]` 循环 → 尾部索引（每 1000 帧一个偏移，支持快速定位与步进回放），可选 zstd 分块压缩（原始字节通常 2\~5 倍压缩率）。

## B7. 线程与并发模型

| 组件     | 模型                              | 说明                            |
| ------ | ------------------------------- | ----------------------------- |
| 串口读    | 每端口 1 个 OS 线程（blocking）+ 无锁环形缓冲 | serialport 是阻塞 API，比 async 更稳 |
| 串口写    | 命令队列（mpsc）+ 单写线程                | 避免交叉写                         |
| 分帧解析   | Tokio 工作线程池（可 rayon）            | CPU 密集                        |
| AI 调用  | Tokio 异步 + 取消令牌                 | 可中断                           |
| SQLite | 单写线程 + WAL                      | 避免锁竞争                         |
| 前端推送   | 独立 batcher 线程                   | 16 ms 节流                      |
