# 客户可自助验证清单（不需要装任何开发工具）

> 这份清单是给**使用者**的，不是给开发的。
> 拿到软件后照着点，10 分钟就能确认「这东西在我机器上是好的」。
>
> 注：桌面版基于 **Tauri 2 + React 19** 构建，推荐使用 Tauri 打包版进行验收和日常使用。

---

## 0. 先跑「整机验收」（最重要）

顶栏 → **✔ 自检 / 验收** → 默认就在「整机验收」页签 → 点 **开始验收**。

它用内置模拟设备真实跑一遍完整链路，**不需要串口、不需要硬件**：

共 **9 组验收标准 / 24 项检查**，全部真实执行：

| 验收标准 | 检查项 |
|---|---|
| 协议解析 | 22 种校验算法可计算；位段/有符号/枚举字段解析正确 |
| 协议编解码 | 组包 → 解包值原样还原；坏帧必须判失败 |
| 通讯调试 | 真发一帧，收到回包并断言通过 |
| 自动化测试 | 断言不满足判失败、空用例判失败、失败即停开/关、if 分支、while 循环、变量自增 |
| CSV 数据驱动 | 表头+数据行解析、3 行跑 3 遍、失败能定位到第几行 |
| 长时间运行 | 无限循环到「最长运行」自动停；运行统计齐全 |
| 报告生成 | 状态 / 步骤 / 耗时 / 压测统计齐全 |
| 数据库存储 | 写入 → 读回 → 清理；协议表可读；报告历史可读取 |
| 桌面运行环境 | 版本号可读、样式已加载、本地存储可读写 |

**全绿 = 软件本身没问题，可以开始用。**

如果有红项：
1. 点 **导出报告**，得到《SerialMind 项目交付验收单》（txt）
2. 把这个 txt 发给支持，里面写明了每项的期望和实际

**全绿时，这份 txt 就是交付依据**：含产品版本、验收时间、运行环境、验收结论、9 组标准对照、24 项明细、双方签字栏。

### 验收结果会留在软件里

验收跑完后，顶栏右上角「⚙」按钮上会出现一个状态点：

| 颜色 | 含义 |
|---|---|
| 🟢 绿点 | 上次验收全部通过 |
| 🔴 红点 | 上次验收有失败项 |
| 🟡 黄点 | 软件版本变过，建议重新验收 |
| 无点 | 还没验收过 |

鼠标悬停能看到「上次验收 24/24 通过 · 时间」。**关掉软件再打开，状态点还在**，不用每次重新跑。

## 1. 确认串口能用

1. 顶栏 → 点串口选择器
2. 看得到你的 COM 口（插着 USB 转串口的话）
3. 参数选对：常见是 **115200 8N1**
4. 点「连接」→ 状态栏变绿

没硬件就用 **模拟设备**（菜单里选「模拟设备 → 连接」），一样能验证收发。

---

## 2. 确认协议能解析

1. 左侧产品树选中子产品 → 顶部 **协议** 页签
2. 看字段列表：帧头 / 长度 / 命令 / 数据 / 校验
3. 底部「调试发送」：改一个字段值 → **组包预览**会实时变化
4. 点 **发送** → 右侧「收发记录」出现 RX / TX 两行，带字段解析

---

## 3. 确认自动化能跑

1. **测试** 页签 → **一键生成示例用例**
2. 点 **运行用例**
3. 自动跳到 **报告** 页 → 看到 1 条记录、通过、耗时
4. 看 **趋势** 面板：柱状图、近 10 次通过率、平均响应

---

## 4. 确认 CSV 数据驱动能用

1. 测试页 → 右侧 **数据驱动** 页签
2. 点 **下载模板** → 得到按你协议字段名生成表头的 csv
3. 填几行数据，保存
4. 步骤里用 `${列名}` 引用
5. 运行 → 每一行跑一遍，全部通过才算通过

---

## 5. 确认无限循环能收住

1. 测试页 → 右侧 **设置**
2. 重复次数填 `0`（无限）
3. 轮间隔填 `1000`（每秒）
4. **最长运行** 填 `10`（秒）
5. 运行 → 10 秒后自动停，报告里写「达到最长运行时长 10s，已自动停止」

---

## 6. 确认报告能导出

报告页右上角：

- **HTML** → 浏览器打开，可直接发给同事
- **JUnit XML** → 能接进 CI
- **复跑失败** → 只重跑失败的用例

---

## 7. 出问题时怎么反馈

| 现象 | 你要做的 |
|---|---|
| 整机验收有红项 | 点「导出报告」发 txt |
| 串口连不上 | 截图顶栏串口菜单 + 状态栏红字 |
| 协议解析不对 | 协议页截图 + 一帧原始 HEX |
| 用例跑不过 | 报告页点「详情」截图 |
| 其他 | 顶栏 **?** 看帮助，里面有完整操作说明 |
