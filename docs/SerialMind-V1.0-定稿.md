# SerialMind V1.0 定稿

> **一个能自己跑起来的 SScom。** 协议和用例配一次，之后每次改完固件点"跑一遍"，它告诉你哪条没过、字节差在哪。**本文合并并取代 V0.1 \~ V0.6**，已删除所有作废内容。之后所有变更都在本文上做增量。

## 2. 对象模型

```
租户 Tenant（客户）            V1 固定 local，只作数据字段
└── 产品 Product  ★主导航      起重机 / 小汽车
    ├── 链路 Link（辅）          COM3 起升PLC · COM5 小车PLC · …（可多条）
    │     └── 协议 Protocol      帧格式、字段、校验、分帧（一条链路绑一个协议）
    ├── 规则 Rule                心跳 / 周期 / 条件触发 / 自动应答
    ├── 用例 Case                步骤 + 断言（可数据驱动）
    └── 套件 Suite               用例集合 → 一键跑 → 报告
```

### 产品为主（三处体现）

| 体现    | 说明                                  |
| ----- | ----------------------------------- |
| 导航主单位 | 顶栏产品切换器，切换产品 = 整套配置全换               |
| 配置归属  | 协议/规则/用例都挂在产品下，；复用 = 复制一份           |
| 导出单位  | 一个 .smprod = 完整可交付物（链路+协议+规则+用例+套件） |

### 链路为辅

* 链路是产品下的**一类资源**，不是独立入口；只有物理参数 + 绑定协议 + 一个备注字符串。
* **没有**角色、没有拓扑、没有健康度、没有监听/模拟/主控三模式。只保留一个勾选：**"只接收不发送"**（纯抓包）。
* **一个产品可挂多条链路**，同时打开互不干扰。

### 多链路并发设计（因为产品可以有多个链路）

| 项    | 设计                                      |
| ---- | --------------------------------------- |
| 并发   | 每条链路独立线程 + 独立缓冲 + 独立状态，互不影响             |
| 端口冲突 | 同一端口不能被两条链路同时打开，打开时即报"已被占用"             |
| 软上限  | 建议 8 条，超过提示"链路过多会影响性能"，但不硬限制            |
| 终端展示 | 默认标签页（一条链路一页）；可选（2\~4 格并排）；可选（多链路交织时间轴） |
| 用例绑定 | 用例必须声明跑在哪条链路上（或"当前激活链路"）                |
| 规则隔离 | 每条链路有自己的心跳/周期规则，互不干扰；全局只有一个"自动发送"总开关    |
| 关闭行为 | 关链路 = 断连但保留配置；删链路 = 进回收站                |

## 3. 协议（PDL）

### 3.1 能力

| 项    | 内容                                                                                                     |
| ---- | ------------------------------------------------------------------------------------------------------ |
| 分帧   | 静默间隔 / 定长 / 分隔符 / 长度字段 / 脚本，可组合                                                                        |
| 字段类型 | uint、int、float、bcd、bool、bitfield、enum、bytes、string(ascii/utf8/gbk)、array、tlv、reserved、nested、timestamp |
| 校验算法 | CRC8、CRC16/MODBUS、CRC16/CCITT、CRC16/XMODEM、CRC32、SUM8/16、XOR8、LRC、BCC、Fletcher、自定义表达式                  |
| 双向   | 同一份定义既能解包也能组包，不存在两套配置                                                                                  |
| 表达式  | 四则/比较/三元 + len、offset、prev.\<field>、bytes\[i]；沙箱求值                                                     |

### 3.2 字段级拆合（唯一保留的"复杂"，因为字节里客观存在）

| 形态          | 说明                      |
| ----------- | ----------------------- |
| 同帧多字节       | 2/4/8 字节量 + 字节序         |
| 跨字段         | 高 16 位在字段 A、低 16 位在字段 B |
| 跨报文         | 高字节在报文 1、低字节在报文 2       |
| 位段          | bits: "3..0"            |
| 有符号补码 / BCD | 内置                      |

**字节序四选一，用户可调**（不锁死默认值）：

| 排布   | 说明   |
| ---- | ---- |
| ABCD | 大端   |
| BADC | 字节交换 |
| CDAB | 字交换  |
| DCBA | 小端   |

配错这四种之一，现场表现就是"数值差 65536 倍"或"高位跑到低位"。配选择器 + 输入已知值实时预览字节流。

### 3.3 强制校验

保存协议前**必须通过样例帧 round-trip**：用该协议组包，结果与用户提供的样例帧逐字节一致。不一致则高亮差异字节，标黄警告或禁止保存（可配）。

### 3.4 协议不复用的落地

* 协议 id 全局唯一（UUID），名字可在产品内重名。
* 复用手段只有两种：**产品内复制**、**从其他产品导入（本质是复制一份）**。
* 修改协议不影响其他产品（因为各产品各自持有一份）。

## 4. 自动发送规则

### 4.1 模型

```
触发器 Trigger ──▶ 动作 Action
                    ├─ 发送报文
                    ├─ 执行用例/步骤序列
                    ├─ 启停其他规则（链式）
                    └─ 置字段值 / 告警 / 延时
```

**规则常驻，用例一次性。** 规则的动作可以是"执行一段步骤序列"——所以"车上线 → 发握手 → 等应答 → 配模式 → 启动心跳"用「触发器 + 步骤序列」就能表达。

### 4.2 触发器

| 类型                    | 例子                |
| --------------------- | ----------------- |
| 周期 `every`            | 心跳 1000ms         |
| 连接建立 `onConnect`      | 打开串口后立即发握手        |
| **信号边沿** `signalEdge` | 某字段 0→1，只触发一次     |
| 信号电平 `signalLevel`    | 持续满足时按周期重复        |
| 信号变化 `signalChange`   | 值变化超阈值            |
| **收到报文** `onFrame`    | 收到查询帧 → 自动回状态帧    |
| **超时** `timeout`      | 心跳应答 N ms 未到 → 重发 |
| 外部 `external`         | 手动 / CLI / HTTP   |

> ⚠️ **边沿 vs 电平必须区分**：`车上线` 用电平触发会每个周期狂发，必须用上升沿。UI 上强制显式选择。

### 4.3 心跳要做完整闭环

发 → 等 ACK → 超时重试 → 连续失败 N 次告警。只发不等 ACK 的"心跳"是假心跳，排障时毫无价值。

### 4.4 发送调度

| 机制   | 规则                         |
| ---- | -------------------------- |
| 优先级  | 手动 > 用例 > 触发规则 > 周期        |
| 队列   | 单链路 FIFO + 优先级插队，溢出告警      |
| 去抖   | 信号触发类强制 cooldown（默认 500ms） |
| 限流   | 全局最大 200 帧/s + 单规则最小间隔     |
| 风暴保护 | 同规则 100ms 内重复触发只执行一次，记录丢弃数 |

### 4.5 来源标记（调试可见性）

`⌨`手动 / `⏱`周期 / `⚡`触发 / `🎬`用例 / `↩`应答 / `🤖`AI。终端可按来源过滤——否则报告里的帧分不清是谁发的。

### 4.6 安全红线

* 顶栏"自动发送"总开关，可一键全停（默认关，连接后提示开启）。
* 危险命令（写/复位/升级/运动）默认**拦截**，需显式授权才允许自动发。
* 新规则首次"预览 3 秒"：只显示将发什么，不发。
* "只接收不发送"模式下强制禁用自动发送。
* 录制回放时默认**不重放**规则（只回放录制帧）。

## 5. 测试引擎（产品本体）

### 5.1 用例 = 步骤 + 断言

```yaml
case: 从1号点位到3号点位
link: ch1
steps:
  - set:    { field: target_point, value: 3 }
  - expect: { field: position,    equals: 3000, within: 3s }
  - expect: { field: in_position, equals: 1,    within: 200ms }
  - assertNo: [crc_error, timeout, unexpected_frame]
```

### 5.2 步骤类型

`send`（原始 HEX）/ `set`（改字段自动组包，最常用）/ `expect`（等待并断言）/ `delay` / `loop` / `parallel`（多字段同时下发）/ `call`（子用例）/ `script`（JS 逃生舱）

### 5.3 断言类型

| 类型   | 说明                             |
| ---- | ------------------------------ |
| 字段值  | equals / range / in / 位段 / 变化率 |
| 整帧字节 | 完全匹配（校验算法回归用）                  |
| 时序   | within / 周期稳定 ±X ms / 顺序       |
| 无异常  | 无 CRC 错 / 无超时 / 无越界 /          |
| 容错率  | N 次里至少 M 次成功                   |

### 5.4 数据驱动

`data: points.csv` + `$row.xxx` 引用 → 一份用例跑 N 行数据，报告按行汇总。把"测 100 个点位"从 100 次手动变成 1 次点击。

### 5.5 执行与报告

| 能力                 | 说明                                |
| ------------------ | --------------------------------- |
| 单步调试               | 一步步执行，每步看实际收发与字段值                 |
| 跑用例 / 跑套件 / 循环 N 次 | 冒烟 / 全量 / 稳定性长跑                   |
| 失败策略               | 失败即停 / 继续收集所有失败（默认）               |
| **失败现场**           | 自动存失败前后 N 秒收发 + 期望 vs 实际 + 字节差异高亮 |
| 一键复跑               | 报告里点单条失败用例直接重跑                    |
| 报告                 | HTML 单文件可分享 + JUnit XML 供 CI      |

### 5.6 回归（日常形态）

* **固件回归**：一键跑全套 → 与上次结果 diff（哪些从过变不过）
* **协议回归**：协议改了 → 自动列出引用它的用例并重跑
* **CI**：`serialmind test run suite.yaml --link COM3 --report out.html --junit out.xml --headless`

* **`Ctrl+Z`****&#x20;撤销**配置操作

## 7. AI（草稿助手）

### 7.1 定位

> **AI 是个打字快的助手，不是老板。它产出草稿，我点"应用"才生效。**

| ✅ 能做               | ❌ 不能做        |
| ------------------ | ------------ |
| 生成草稿：协议、链路配置、用例、数据 | 直接写入生效       |
| 填充表单、给建议           | 自动修改已有配置     |
| 解释、分析、找原因          | 自动发送 / 自动跑测试 |
| 从文档、录制、一句话推断       | 替我决定任何事      |

### 7.2 草稿区

AI 产出全进草稿区：**带 diff 预览** + **标出待确认项** + **可逐条应用** + **应用后可撤销**。

### 7.3 权限分级

| 级别             | 行为            |
| -------------- | ------------- |
| **L0 关闭**      | 完全不调用，所有功能照常  |
| **L1 只建议（默认）** | 输出草稿，我手动应用    |
| **L2 自动填充**    | AI 填表，我点保存才生效 |
| L3 自动应用        |               |

### 7.4 三条硬约束

* **AI 可完全关闭**，关掉后所有功能照常——手动 CRUD 是完整的第一等能力。
* **不许静默改配置**：必须有 diff + 我确认 + 审计日志。
* **猜测必须标出来**：文档没写清的字段、不确定的校验算法、推断的字节序，一律高亮"待确认"。

### 7.5 协议文档 → PDL（防幻觉闭环）

| 环节         | 做法                                       |
| ---------- | ---------------------------------------- |
| 预处理        | C 头文件 / 表格走（tree-sitter、行列对齐），LLM 只补人话描述 |
| 抽取         | 两级：Pass A 帧骨架，Pass B 逐字段细化               |
| **校验器**    | 字段连续性、长度自洽、round-trip、枚举合理性              |
| **校验算法判定** | 用样例帧自动判定（这是算得出来的，不该问模型）；多命中让用户选，零命中标红    |
| 自纠错        | 失败回喂错误信息重试 ≤3 轮，仍失败降级为"部分完成"             |

### 7.6 AI 辅助测试（4 种）

| 用法              | 说明                                    |
| --------------- | ------------------------------------- |
| ① 一句话生成用例       | "测 1 号点位到 3 号点位，位置 3 秒内到 3000" → 用例草稿 |
| ② **从录制生成用例** ★ | 我先手动跑通一遍，它把交互转成用例骨架，我只补断言（最可靠）        |
| ③ 补断言           | 建议"还漏了 CRC 检查、漏了无多余帧"                 |
| ④ 失败分析          | 期望 vs 实际 + 原始字节 → 可能原因排序              |

## 8. 界面

### 8.1 主界面

```
┌─ 顶栏：[产品 起重机 ▾] ─ COM3 921600 8N1 ─ RX/TX ─ [自动发送 关] ─ 运行 ─┐
├──────────┬──────────────────────────────────────┬──────────────────────┤
│ 产品树    │ 终端（虚拟滚动 · 字段级着色）           │ 检查器                │
│ 链路      │ 14:32:07.412 ← #1284 01 03 14 00…     │ 字段树 / 曲线 / 规则   │
│ 协议      │   └ 地址=1 功能=03 数据=[250,251]     │                      │
│ 规则      │ 14:32:07.432 ← #1286 ⚠ CRC 错误       │                      │
│ 用例      │                                        │                      │
├──────────┴──────────────────────────────────────┴──────────────────────┤
│ [HEX] 01 03 00 00 00 0A C5 CD      [发送] [定时▾] [AI /]                │
└────────────────────────────────────────────────────────────────────────┘
```

管理区和收发终端是**同一窗口的两个视图**，随时切换或分屏——管理不是"设置页"。

### 8.2 视觉规范

* 暗色优先，6 套主题（Midnight / Carbon / Daylight / Solarized / High Contrast / Nord），支持导入
* 字体：UI = Inter + 思源黑体；等宽 = JetBrains Mono + **Sarasa Mono SC**（中文双宽对齐）
* 语义色：TX `#22D3EE` / RX `#4ADE80` / 错误 `#F87171` / 警告 `#FBBF24` / AI `#A78BFA`
* 动效 120–200ms，只用于状态变化；最小可点区 28×28
* 色盲友好：TX/RX 除颜色外另有 `→`/`←` 图标

## 9. 技术架构

| 层         | 选型                                                     |
| --------- | ------------------------------------------------------ |
| 外壳        | （包体小、内存低、权限细、Rust 适合串口）                                |
| 前端        | React 19 + TypeScript + Vite 7 + Tailwind 4 + Radix 原语 |
| 虚拟滚动 / 图表 | TanStack Virtual / uPlot + ECharts（按需）                 |
| 后端        | Rust + Tokio                                           |
| 串口        | serialport crate + 每端口阻塞读线程                            |
| 存储        | 本地 SQLite + 本地文件                                       |
| 脚本        | rquickjs（QuickJS 沙箱）                                   |

### 9.1 高吞吐通道（关键）

```
串口线程 → Rust 侧分帧 → 批量聚合（16ms 或 64KB）
       → Tauri Channel 二进制推送（非 JSON event）
       → 前端环形缓冲 → 虚拟列表只渲染可视区
```

分帧在 Rust 做；二进制 IPC 比 JSON 快 5\~10 倍；背压时丢弃"显示用"数据但**完整落盘**。

### 9.2 数据模型（本地优先 + 为云端预留）

| 表                                                    | 说明            |
| ---------------------------------------------------- | ------------- |
| `product` / `link` / `protocol` / `protocol_version` | 产品、链路、协议与版本   |
| `rule` / `rule_stat`                                 | 自动发送规则与统计     |
| `case` / `case_step` / `assertion` / `suite`         | 用例、步骤、断言、套件   |
| `run` / `run_item`                                   | 运行记录与结果       |
| `draft`                                              |               |
| `audit_log`                                          | 审计（含 AI 应用记录） |

**六条预留（成本 < 3 天，省掉将来一次迁移）**：

* 主键用 **UUIDv7**（不用自增）
* 所有表带 `tenant_id`（V1 固定 `local`）
* 时间全存 **UTC**
* `created_at` / `updated_at` / `deleted_at` / `rev`
* 导出文件带 `schemaVersion` + `tenantId`
* 数据访问走 **Repository 层**，不散落 SQL

> 有了这六条，将来上云端不是架构重构，是加一层（登录+租户绑定 → Remote 实现 → **产品级同步** → 冲突"谁新谁赢+另存一份"）。

### 9.3 跨平台

Windows 10 1809+ / macOS 12+ / Ubuntu 20.04+（x64 + arm64）。Win 需签名、mac 需公证、Linux 提供 AppImage + deb。

## 12. 待确认（3 个，不影响开工）

* **用例你自己写，还是 AI 生成后你改？** → 决定"从录制生成"提前还是放 V1.1
