# SerialMind 解决方案说明

## 一、客户有哪些问题

### 设备协议靠 Excel 维护

#### 客户痛点
- 协议版本容易混乱
- 字段解释不统一
- 人员交接困难
- 文档与设备不一致

#### SerialMind 如何解决
- 图形化协议建模
- 协议版本统一管理（点标题旁的版本号即可改名称 / 版本，改动会写入协议记录）
- 自动生成协议解析规则
- 协议资产沉淀与复用（协议可复制、可跨子产品复用）

#### 客户价值
- 降低沟通成本
- 减少联调时间
- 缩短交付周期
- 提高项目可维护性

## 四、客户验收标准

软件内置的「整机验收」与下表 **1:1 对应**，运行后逐项给出通过/失败：

| 序号 | 验收标准 | 软件里的验证方式 |
|---|---|---|
| 1 | 协议解析正确 | 22 种校验算法可计算；位段 / 有符号 / 枚举字段解析正确 |
| 2 | 协议编解码正常 | 组包 → 解包值原样还原；坏帧必须判失败 |
| 3 | 通讯调试正常 | 真发一帧，收到回包并断言通过 |
| 4 | 自动化测试执行成功 | 断言不满足判失败、空用例判失败、失败即停开/关、if 分支、while 循环、变量自增 |
| 5 | CSV 数据驱动执行成功 | 表头+数据行解析、3 行跑 3 遍、失败能定位到第几行 |
| 6 | 长时间运行稳定 | 无限循环到「最长运行」自动停；运行统计齐全 |
| 7 | 报告生成成功 | 报告含状态 / 步骤 / 耗时 / 压测统计 |
| 8 | 数据库存储正常 | 写入 → 读回 → 清理；协议表可读；报告历史可读取（趋势/通过率数据源） |
| 9 | 桌面运行环境正常 | 版本号可读、界面样式已加载、本地存储可读写 |

全部通过后，点「导出报告」得到《SerialMind 项目交付验收单》，含验收结论与签字栏，**可直接作为项目交付依据**。

## 六、推荐客户验收方式

1. 打开软件
2. 点击顶栏【✔ 自检 / 验收】（默认停在「整机验收」）
3. 点【开始验收】
4. 查看 9 组验收标准与 24 项检查明细
5. 点【导出报告】，得到《SerialMind 项目交付验收单》

验收通过标准：

- 9 组验收标准全部 ✓
- 24 项检查明细全部「通过」
- 验收结论显示「通过（可作为交付依据）」

《项目交付验收单》包含：产品名称、版本、验收时间、运行环境、验收结论、验收标准对照表、检查明细、签字栏。

验收结果同时留在本机：顶栏右上角「⚙」出现状态点（绿=通过 / 红=有失败 / 黄=版本变更需重验），悬停可见上次验收时间与结果。客户关掉软件再打开，仍能一眼看到「这台机器上次验收是好的」。

**验收结果可直接作为项目交付依据。**
