# 自动化配置指南（照着点就行）

> 目标：配一套能自动跑、能看报告、能复跑失败项的自动化测试。
> 全程只需要点鼠标，不用写代码。

---

## 先理解 4 个词（其余的先不用管）

| 词 | 一句话解释 | 你要不要配 |
|---|---|---|
| **产品 / 子产品** | 产品是"这台机器"，子产品是"里面的一个功能模块"（起升控制 / 小车控制） | 要，1 分钟 |
| **协议** | 帧格式：一帧多少字节、哪段是帧头、哪段是数据、校验怎么算 | 要，已有 PLC 默认模板 |
| **用例** | 发什么 + 断言什么。一条用例 = 一个测试点 | 要，核心 |
| **套件** | 一批用例打包一起跑（按标签筛），在「测试」页顶部切换 | 想批量跑才要 |
| 角色 / 规则 | 角色=总线上的身份（站号）；规则=常驻触发器（心跳）。**自动化测试用不到** | 不用管 |

## 5 步配置

### 第 1 步：建产品和子产品

1. 顶栏左上角点产品名 → **新建产品**（例：`起重机`）
2. 左侧「产品结构」点 **+** → **新建子产品**
3. 名称填 `起升控制`，协议类型保持 **PLC 默认** → 创建

创建完，左侧树里就有：

```
起重机
└── 起升控制
    └── 协议
        └── 起升控制·主协议   ← 已经帮你建好 7 个字段
```

### 第 2 步：确认协议帧结构（大概率不用改）

> 协议名称和版本号：点标题旁的灰色版本号标签即可修改，报告和验收单里会用它标识协议。

点协议进入「协议」页，应该是：

| 字段 | 类型 | 长度 | 值 |
|---|---|---|---|
| header | bytes | 2 | `DE 21` |
| len | uint | 1 | 自动 |
| lenInv | uint | 1 | 自动 |
| cmd | uint | 1 | `60` |
| data0 | uint | 1 | `01` |
| data1 | uint | 2 | `0000` |
| sum | crc | 1 | 自动 |

底部「调试发送」的**组包预览**应该是 `DE 21 09 F6 60 01 00 00 5F`。

- 不一样就改「值」列（十六进制直接填）
- 要改帧头：header 行的「值」列填你的帧头，如 `DB 24`
- 帧结构完全不同：协议页 → 「从样例帧建」→ 粘一帧真实报文 → 切分

### 第 3 步：连串口（或先用模拟设备自测）

**真机**：顶栏「选择串口」→ 选 COM 口 → 选波特率 → 连接

**没有硬件也想试**：顶栏「选择串口」→ 选 **模拟设备（回环）** → 连接
（发出去的字节会原样回来，用来验证"发→收→断言"整条链路）

### 第 4 步：建用例（核心）

1. 上方页签点 **用例**
2. 点 **一键生成示例用例** ← 会自动建好 2 个步骤
3. 生成的内容长这样：

```
步骤 1  send    DE 21 09 F6 60 01 00 00 5F     ← 发这一帧
步骤 2  expect  cmd equals 96                  ← 等回包，断言 cmd = 0x60
```

4. 想改就点步骤行编辑：

| 步骤类型 | 什么时候用 | 怎么填 |
|---|---|---|
| `send` | 发一条固定帧 | 「值/断言」填 HEX，如 `DE 21 09 F6 60 01 00 00 5F` |
| `expect` | 等回包并断言 | 字段填 `cmd`，「值/断言」填 `equals 96` |
| `set` | 改字段值后自动组包发 | 字段 `data1`，值 `= 530` |
| `assertNo` | 断言不该出现某异常 | 填 `crc_error` |
| `delay` | 等一下再继续 | 填 `500ms` |

**断言写法**（写在「值/断言」里）：

| 写法 | 意思 |
|---|---|
| `equals 96` | 等于 96 |
| `range 100..200` | 在 100~200 之间 |
| `in 1,3,5` | 是 1、3、5 之一 |
| `> 100` / `< 50` | 大于 / 小于 |

**超时**：`2s` 或 `500ms`，超时还没满足就判失败。

### 第 5 步：运行 → 看报告

1. 用例页右上角 **运行用例**
2. 自动跳到 **报告** 页：

| 列 | 含义 |
|---|---|
| ✓ / ✗ | 通过 / 失败 |
| 用例 | 用例名 |
| 耗时 | 这一轮跑了多久 |
| 失败原因 | 哪一步、期望什么、实际什么 |

- 刷新、重启，报告都还在（存数据库）
- 「复跑失败 N 项」只重跑上次失败的
- 「HTML」/「JUnit XML」可导出给别人看

## 想让测试会判断：if / while / 变量

自动化不是「一条条往下跑」，要有判断和循环。

### 加一个 if

1. 测试页 → 步骤栏 **+ 步骤**
2. 类型选 **if — 条件分支**
3. 条件写 `position > 100`（左边可以是回包字段，也可以是变量）
4. 点添加 → 这一行下面出现「条件成立 / 否则」两个框
5. 点 **添加子步骤**，往里加要执行的步骤

条件支持：

```
position > 100        position >= 100      position < 50
position <= 50        position == 3000     position != 0
position equals 3000  position range 1..9  position in 1,3,5
position exists       position notexists
```

### 加一个 while

类型选 **while — 条件循环**，条件 `score < 3`，上限填 `10`。
循环体里放 **setVar** 改变量，条件不成立就退出；到上限强制停，不会跑飞。

循环体里可以放 **break**（跳出）和 **continue**（进入下一轮）。

### 变量

类型选 **setVar — 变量赋值**：

```
score = 0
score = score + 1
score = score * 2
```

变量可以直接用在条件里，也可以在 expect 里用 `${score}`。

### 完整例子

```yaml
steps:
  - setVar: score = 0
  - while: { score < 3, max 10 }
    do:
      - setVar: score = score + 1
      - if: { score == 2 }
        then:
          - send:   "DE 21 09 F6 60 01 00 00 5F"
          - expect: { field: position, equals 3000, within 2s }
        else:
          - delay:  100ms
```

含义：score 从 0 加到 3；只在 score==2 那一轮发帧并断言。

> 条件里的字段取的是**最近一帧回包**的值，所以 `if` 前面要先有 `send` 或 `expect` 收到过帧。

## 想更自由：直接写 YAML

可视化「+ 步骤」是入口；要更细的控制，直接改 YAML。

1. 测试页 → 用例 → 下方 **YAML** 卡片 → 点 **编辑**
2. 直接写（格式就是预览里那套）：
3. 点 **应用** → 立刻变成可视化步骤，两边同步

```yaml
steps:
  - set:    { field: position, value: 3000 }
  - expect: { field: position, equals 3000, within 2s }
  - assertNo: [超时, 掉线]
  - send:   "DE 21 09 F6 60 01 00 00 5F"
  - delay:  500ms
  - loop:   10
  - parallel: [position=3000, speed=0]
```

支持的 7 种步骤：

| 写法 | 作用 |
|---|---|
| `set: { field: X, value: Y }` | 改字段并组包发送 |
| `expect: { field: X, equals 3000, within 2s }` | 等回包并断言 |
| `assertNo: [超时, 掉线]` | 窗口内不许出现这些 |
| `send: "DE 21 ..."` | 发原始字节 |
| `delay: 500ms` | 等待 |
| `loop: 10` | 循环 |
| `parallel: [a=1, b=2]` | 多字段一次发送 |

断言写法：`equals 3000` / `range 1000..4000` / `in 1,3,5` / `> 100` / `< 50`。

写错了点应用会**逐行报错**（第几行、缺什么），原步骤不会被改坏；点取消直接丢弃。

## 想批量跑：套件

1. 页签 **测试** → 顶部切到 **套件** → 新建套件
2. 填套件名 + **标签**（如 `冒烟`）
3. 到用例页给用例打上同样的标签
4. 套件页点「运行套件」→ 一次跑完所有带该标签的用例

> 标签留空 = 跑该产品的全部用例。

---

## 想一个用例跑多组数据：数据驱动

1. 用例页 → 右侧 **数据驱动** 页签
2. 三种方式任选：
   - 点 **下载模板**：按当前协议的字段名自动生成表头，照着填
   - 点 **选择 CSV 文件**：直接选 .csv（Excel 导出的中文 GBK 也能认）
   - 把 .csv **直接拖进文本框**
3. CSV 格式（首行列名，一行跑一次）：

```csv
want,note
96,第一行
96,第二行
```

4. 步骤里用 `${want}` 引用：

```
expect  cmd  equals ${want}
```

5. 运行 → **两行都通过才算通过**，有一行失败就停并报告是第几行。

> 载入成功会提示「文件名 · N 行数据」，用例卡片上显示 `CSV 3 行`。

## 常见问题

**Q：报告里显示「不符合当前协议」**
A：收到的帧和协议对不上（长度或帧头不符）。去协议页核对 header 和字段总长度。

**Q：断言一直超时失败**
A：三种可能——① 串口没连；② 协议帧头/长度配错，回包解不出来；③ 断言的值不对。
先看终端页有没有收到 RX 帧，有的话看字段解出来是多少。

**Q：我想改发送的字节但不想改协议**
A：调试发送面板里，除了 len/反码/sum（自动计算），其余字段都能直接改，包括固定帧头。
改动只影响这一次发送，不写回协议。

**Q：字段值是十进制怎么办**
A：调试发送面板里点字段名右边的 `HEX` 切成 `10进制`，填 530 会自动转成 `02 12`。

## 一句话总结

```
建产品/子产品 → 确认协议 → 连串口 → 一键生成示例用例 → 运行 → 看报告
```

跑通这一条，剩下的（套件、数据驱动、复跑失败）都是在这上面加东西。

## 实战：心跳 + 车辆上线 + 得分每秒 +1

这是一套完整配置，照着填就行。

### 用例步骤（测试页 → 步骤 → + 步骤）

| # | 类型 | 字段 | 值/断言 | 说明 |
|---|---|---|---|---|
| 1 | `send` | — | `DE 21 09 F6 60 01 00 00 5F` | 上线通知帧（只发一次） |
| 2 | `set` | `data1` | `${score}` | 得分，每轮自动变 |
| 3 | `expect` | `cmd` | `equals 96` | 断言设备回了正确命令 |

### 运行设置（测试页 → 右侧「设置」）

| 项 | 填 | 含义 |
|---|---|---|
| 重复次数 | `0` | **0 = 无限循环**（心跳常驻），点「停止」才结束 |
| 轮间隔 | `1000` | 每秒一轮 |
| 失败重试 | `1` | 偶发丢帧重试一次 |
| 变量 | `score=0+1` | 第1轮 score=0，第2轮 1，第3轮 2… |

### 跑起来是什么效果

```
第 1 秒：发 DE 21 09 F6 60 01 00 00 5F   然后 data1=0 发 DE 21 09 F6 60 01 00 00 5F
第 2 秒：data1=1 → DE 21 09 F6 60 01 00 01 60
第 3 秒：data1=2 → DE 21 09 F6 60 01 00 02 61
...
校验和每轮自动重算，不用管
```

- **上线帧**：第 1 步只在**第一轮**发一次？不是——它在每轮都发。如果只想连上发一次，把它从用例里拿掉，改成顶栏连串口前手动发一次。
- **停止**：运行中按钮会变成「停止」，点一下就结束，报告照常生成。
- **统计**：报告里每行显示 `发 N · 收 N · 丢 N · 均 Xms`。

### 无限循环时怎么收尾

点「停止」→ 用例结束 → 报告里记一条，含发了多少帧、丢了多少、平均响应。

> 想真正"开机就自动跑、不点运行"——那属于常驻规则（已从界面移除），需要单独做。
---

## 无限循环怎么收尾：最长运行 / 失败即停

用例页 → 右侧 **设置**：

| 设置 | 填什么 | 作用 |
|---|---|---|
| 重复次数 | `0` | 无限循环（心跳） |
| 轮间隔 | `1000` | 每秒一轮 |
| **最长运行** | `3600` | 最多跑 1 小时，到点**自动停**，报告写「达到最长运行时长」 |
| **失败即停** | 开（默认） | 某步失败立刻停；关掉则跑完剩余轮次，最后整体判失败 |

> 以前无限循环忘了点停止会一直跑，现在填了「最长运行」就不用守着。

---

## 报告趋势怎么看

报告页 → **趋势** 面板：

- 柱状图：最近 30 次运行，**柱高 = 耗时**，**绿 = 通过 / 红 = 失败**
- 近 10 次通过率
- 平均响应 / 最大响应（没有收发数据时显示 `—`）
- 累计发送帧数

## 用 AI 从文档生成协议

顶栏 **AI** → 左侧贴协议文档（字段表格 / C 结构体 / 样例帧都行）：

- **本地抽取（无需 Key）**：确定性解析，不联网、不猜
- **调用模型生成**：需要自己的 Key

配置 Key：点 **模型设置** → 填 Base URL / API Key / 模型 → 点 **测试连接**：

- 绿字 `连通 · deepseek-chat · 420ms` → 可以用
- 红字 `HTTP 401：...` → Key 不对
- 红字 `网络错误：...` → 地址不对或被墙

兼容 OpenAI 协议：DeepSeek / 通义 / Kimi / 本地 Ollama 都能填。

## 怎么确认软件是好的：自检 / 验收

顶栏 **✔ 自检** 按钮，两个页签：

### 整机验收（推荐先跑这个）

用内置模拟设备**真实跑一遍完整链路**，不需要硬件、不占串口。

共 **9 组验收标准 / 24 项检查**：

| 验收标准 | 检查内容 |
|---|---|
| 协议解析 | 22 种校验算法、位段/有符号/枚举字段 |
| 协议编解码 | 组包↔解包还原、坏帧必须判失败 |
| 通讯调试 | 真发一帧 → 收回包 → 断言通过 |
| 自动化测试 | 断言失败判定、空用例、失败即停开/关、if 分支、while 循环、变量自增 |
| CSV 数据驱动 | 解析、3 行跑 3 遍、失败定位到第几行 |
| 长时间运行 | 无限循环到点自停、运行统计 |
| 报告生成 | 状态/步骤/耗时/统计 |
| 数据库存储 | 写入 → 读回 → 清理；协议表 / 报告历史可读 |
| 桌面运行环境 | 版本号、样式加载、本地存储 |

全部通过 = 软件本身没问题。

点 **导出报告** 得到《SerialMind 项目交付验收单》：含产品版本、验收时间、运行环境、验收结论、9 组标准对照、24 项明细、双方签字栏，**可直接作为项目交付依据**。

有失败时同样导出发给支持，里面写明了每项的期望和实际。

验收完顶栏「⚙」会出现状态点（绿=通过 / 红=有失败 / 黄=版本变了要重验），悬停看上次验收时间。关掉软件再打开，状态点还在。

### 引擎自检

纯算法层：校验向量、字节序四排列、位组合、断言求值、帧识别。

> 客户拿到软件第一件事：跑一遍「整机验收」。全绿再开始用。
